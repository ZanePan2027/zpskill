# 下次接着用：搭子记得共同经历，陪你继续

[English](continue.en.md) · [第一次使用](first-task.md) · [手册目录](README.md)

人生搭子的陪伴，靠共同经历一点点生长。为了下次还能接上，搭子需要能找回你们的共同背景。zpskill 的接续依赖你授权的工作台文件，以及当前 Agent 实际能访问的内容；它不是每个 AI 客户端都自动共享的记忆服务。

## 选一个你准备长期使用的文件夹

在 Agent 里打开这个文件夹，再说：

```text
使用 zp-workspace，沿用这个文件夹建立够用的人生工作台。
先保留已有文件和规则；只保存对后续有用的背景、当前判断和成果。
不要为了建台耽误我眼前这件事：……
```

Skill 安装目录放方法；工作台文件夹放你的资料与进展。两者分开，更新 Skill 时才不会把私人资料当成安装文件覆盖。已有目录也可以沿用，不需要再做一套画像。

## 结束前留一个能继续的位置

```text
请保存我们已经确认的背景、现在的判断和这份成果，标明下一步。
把你的推测与我确认的事实分开；哪些还没有发生，也写清楚。
```

保存什么由当前宿主权限和你的意愿决定。不要把所有倾诉或第三方隐私都长期保留。想纠正或撤回某条认识时直接说明，让 AI 同步修正依赖它的判断。

## 下次在同一个项目继续

```text
接着上次。先找回那件事的背景、成果和停下的位置。
我有一个新反馈：……。请先修改原来的判断，再继续下一步。
```

一次好接续应能指出正在继续哪件事、上次做到哪里、这次反馈改变什么。若 AI 找不到，就定位原文件或告诉它所在位置；不要让它假装记得。

换客户端时，需要让新客户端得到同一工作台的文件访问权，或由你选择性迁移资料。安装同一套 Skills 本身不会转移聊天历史和私人资料。

## 从现实里检查有没有用

例如，上次只是写好了沟通提纲，这次你真正沟通过了，就记录发生了什么；没有沟通就保留“尚未执行”。反馈回来后原建议是否改变，比新增了多少记录更重要。

工作台文件在你选择的位置保存；调用外部模型或云端 Agent 时，数据处理仍取决于该客户端和服务。只提供这次任务需要的资料。安装细节见[安装与更新](install.md)，文件如何生长见[工作台结构](architecture.md)。
