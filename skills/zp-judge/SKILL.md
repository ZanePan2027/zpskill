# 判断与决策

把“要不要改”这类决定，从凭感觉改成：钉清决定、分清证据、两边都被反驳过、定好翻转条件、只做一个最小实验、事后回填。方法的取舍依据见 [来源与边界](references/provenance.md)。

## 什么时候用，什么时候不用

用：决定有成本或不好撤回；证据少或有噪声；你已经倾向某个答案；要对一批后续动作定调（例如接下来所有视频要不要改）。
不用：一键可撤、几乎没成本的小事，直接做。人生方向、关系、搬家这类选择，先走 `zp-life`，再回到这里处理其中的具体决定。

## 和 zp-question 怎样搭配

两个技能首尾相接，不合并：

```text
说不清要问什么／不会写给 AI ──→ zp-question：把原话转成进展、当前决定、可用问题
                                      │
                                      ▼
                          zp-judge 必要性闸门：值不值得问？是不是伪命题？
                          ├─ 不成立 → 直说原因，给小行动或“不做”，省下时间和 token
                          ├─ 半成立 → 改写问题，回 zp-question
                          └─ 成立   → 往下走：证据、反方、结论、最小实验
```

- 只是想把话说清、直接要答案：用 `zp-question`，不必走判断流程。
- 已经有明确决定、要判断改不改：直接用本技能。
- 决定本身是人生方向的选择：先 `zp-life`。

## 流程

**0. 目的。** 这个决定为了什么？指标（播放、点赞、涨粉）是手段，不是目的。写一句：它服务于哪个更大的目的，以及如果指标好看但目的没动，算不算成功。

**1. 钉决定。** 一句话写清要决定什么；如果用户自己都说不清要什么，先用 `zp-question` 把问题问对，再回来。列出所有选项，**“不动”也是一个选项**；谁来决定、多久内必须定、动了能不能撤回。

**1.5 必要性闸门。** 先判断这件事成不成立、值不值得做，细则见 [必要性闸门](references/necessity-gate.md)。结论三种：成立就继续；不成立就直说哪一项没通过，并给一个小行动或“不做”；半成立就改写问题，交给 `zp-question`。不凭“听起来没用”否定休息、关系、兴趣这类有直接价值的事。

**价值冲突型决定。** 如果卡住的不是证据，而是两样都想守护的东西（比如陪父母还是留在大城市），数据不会替他定，不要硬走证据账。改成价值澄清：每个选项分别守护什么、放弃什么；十年后回看，哪一个更让他不后悔；这是谁的事、谁的课题。把答案交给他自己拿，再回 `zp-life` 排路线。这类“课题分离”的提问是引导思路，不当作有实证的结论。

**闸门之后怎么收尾**（不要无条件走完整决定卡）：
- 不成立或半成立：只做三件事——说明哪一项没通过、改写问题或给一个小行动、问一个会改变答案的问题。不出决定卡。
- 成立，但事情小、可撤回、几乎没成本：用一句话版——对“做”“不做”各一句反驳，一个小实验，一句翻转条件。用户明确要求“先反驳我一下”的小事，同样走一句话版。
- 成立，且成本高、难撤回、证据薄：才走下面的完整流程。

**2. 证据账。** 把已知的每条信息标上等级，一行一条：
- **[实]** 直接看到的数字或原话；**[算]** 由实数换算；**[经]** 行业经验值，不是平台标准；**[推]** 你的推断；**[未知]** 没有数据。
- 每个比率写样本量和窗口，小样本用 `scripts/rate_interval.py` 算区间，别拿几个点击当趋势。细则见 [证据与样本](references/evidence-and-sample.md)。

**3. 定位。** 问题出在链条的哪一层？每层只有“有信号／没信号／未知”三种，数据不全的层写未知，不补猜。内容数据的常用分层：曝光 → 开头留人 → 持续观看 → 互动 → 关注 → 承接。哪一层有信号，决定才有对象。

**4. 反方先行。** 对每个选项各做一轮反驳，规则见 [反方协议](references/counter-argument.md)。要点：反驳**做**，也反驳**不做**；每条异议必须引这件事的事实，并写出“什么观察能证明它对或错”；最多五条，按“会不会改变决定”排序。

**5. 支持方。** 同样的规则，列出每个选项成立的核心理由，同样要有事实和可检验的观察。

**6. 中立比较。** 哪一边有证据，哪一边只是猜测；哪些异议可以用数据检验、多久能拿到。不要为了平衡而五五开：证据不对称就写不对称。

**7. 下结论。** 只有三种结论，必须选一种：
- **现在改**：满足下面任一条——① 结构性缺口，不依赖数据就成立（例如发布的内容介绍了某个产品，却没写在哪里拿）；② 数据信号大于噪声（区间不跨参照线，且有对应的机制解释）；③ 成本约等于零、可撤回，并且这一步本身能产生信息。
- **不改**：成本高而证据弱，或改动没有对应到有信号的那一层。
- **再观察**：只有在同时写明下面两项时才允许——到哪一天看什么指标、超过或低于多少就改（观察前定好，不能看完数据再定）；以及在此之前现在就能做的一个取数据的具体动作。
不允许只写“数据太少，再等等”。

**8. 翻转条件与最小实验。** 写清“出现什么，就推翻这个结论”。要改的东西一次只改**一个变量**，写好指标、窗口、判断线。

**9. 回填。** 到期把实际结果填回决定卡，原结论不改写，只追加。自己的结论和 AI 的推测分开标，不把事后才知道的东西倒灌回当时的判断。

## 决定卡（输出格式）

```
决定：……（选项：A / B / 不动）
目的：……
证据账：[实]… [算]… [经]… [推]… [未知]…
哪一层有信号：……
反方（做／不做各一轮）：……
支持方：……
比较：……
结论：现在改 / 不改 / 再观察 —— 依据：……
翻转条件：……
最小实验与观察日：……
回填：（到期填）
```

## 红线

- 不拿 3～5 个互动或一两百次播放下“这条好／不好”的结论。
- 不把平台算法、完播率阈值当事实讲；只能当待验证的假设并标 [经]。
- 不用“信息不够”来逃避决定，也不用“再准备一下”代替动手；该动手的就给动作。
- 不一次改多个变量；不在看到结果后才回头定判断线。
- 反方只是检查工具，不是裁判：被反驳完也不代表该放弃；没有事实支撑的异议要删掉。
- 流量不是收入也不是目的；指标好看但目的没动，不算成功。
