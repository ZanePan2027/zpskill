# BOSS直聘等招聘平台与投递

## 从招聘者实际看到的触点开始

优先使用当前岗位JD、在线简历文字、消息内容及用户提供的界面。BOSS直聘这类平台以在线资料和沟通推进求职；列表、聊天、完整简历和附件各承担不同任务，不能用一份长自我介绍覆盖所有位置。

| 位置 | 内容任务 | 常见改法 |
|---|---|---|
| 在线简历可见开头／个人优势首句 | 让对方迅速识别相关性与一个可信优势 | 把岗位方向、相关经历或代表产出提前，删“本人性格开朗”等空开场 |
| 完整在线经历 | 呈现职责、工作内容与证据 | 按平台实际字段组织，和附件硬事实一致，避免整页文档粘成一段 |
| 首条消息 | 给这一个岗位一个继续交流的理由 | 具体岗位需求＋一项对应经历；未知不假装匹配 |
| 回复HR、交换附件与约面试 | 回答对方当前问题并推进下一动作 | 先答所问，再补相关证据；可到岗时间等承诺用已知事实 |
| 附件简历 | 供完整筛选、保存或转交 | 独立可读、易扫读，文字可选取，适合实际格式限制 |
| 作品集 | 验证作品与处理问题的能力 | 只提供与岗位相关的入口，避免一开始抛一堆链接 |

## 首句、字数与当前界面

先区分输入上限、招聘者可见预览和平台生成的AI推荐理由。既有桌面截图中，推荐列表两条中文样本均露出22字符，普通搜索两条样本露出57、60字符；具体测算见[界面依据](platform-evidence.md)。起稿先以20—22个中文字完成一项岗位价值，前约50—60字补足经历，后文展开。新截图或明确字数要求优先。

即使无法核实截断长度，也能交付有用首句：把最相关且有依据的信息放前面，让前半句独立有意义，再给完整展开版。用户明确给出X字要求时遵守并在内部实际计数；能观察界面时再检查实际截断，不把字符计数当像素宽度。

合成例：有校园活动经历、目标活动运营的应届生，可用“活动运营方向｜做过报名与现场执行”；正文再给活动规模与本人任务。对有经验者，开头优先其实际岗位与代表成果，不统一包装成“潜力新人”。不要为吸引点击夸大年限、职级、管理人数或就业状态。

## 先看实际功能，再提供操作

附件格式/大小、个人优势长度、招呼设置、交换资料、外链、招聘者状态与屏蔽选项会随端和版本变化。以当前可见界面、帮助说明或官方来源为准；记录核查时间，未知就不要写成保证可用。不把用户账号内容自动同步到其他网站。

只有用户请求操作且当前工具有访问能力时才执行；写好文字不等于已更新在线简历或已发送。在线个人资料更新也按用户明确指定的内容和范围执行，发送对象、附件版本与实际完成结果需要对应。

## 形成可用投递组合

用户要“在BOSS上怎么呈现自己”时，可以交付在线简历首句/个人优势、目标岗位招呼语、附件简历调整与是否需要作品集的判断。用户只要招呼语时只给这条消息，不扩成全套制作。

同一岗位的在线资料、附件与面试说法保持事实一致；不同岗位允许突出不同经历，不改职称、时间和结果。未拿到具体JD时基于已知岗位方向做可用基础版，并只指出真正影响定制的缺口。

## 先看掉在哪一步

用一张简单的漏斗看：投递数、被查看数、有沟通数、约到面试数、过终面数、拿到 offer 数。哪一级掉得最多，改哪一份材料：被查看少，改在线简历首句和岗位选择；有查看没沟通，改首条消息；有沟通没面试，改附件和硬条件；面了没下文，回到[面试素材库](story-bank.md)。他从“我不行”换成“第二步掉得最多”，才有可改的地方。

## 不止一个渠道

校招和实习常用的路径是内推加官网投递，只覆盖一个平台会漏掉一大半。牛客适合看面经、做笔试；脉脉、LinkedIn 适合找内推和联系人；官网投递适合有明确岗位又没有内推的情况。内推请求怎么写交给 [zp-greeting](../../zp-greeting/SKILL.md)。各平台功能和规则随版本变化，沿用上面“记录核查时间、未知不写保证”的做法。

## 从反馈调整

把“尚未查看、已读未回复、沟通后停止、邀约后取消、面试后未推进”等实际可见信号分开。界面没有提供的状态保留未知。少量无回复不能证明学历无效、能力不足或平台限流。

按招聘链路定位：岗位是否真实匹配和仍开放、首句是否清楚、证据是否相关、消息是否回答招聘者所问、附件是否可读、到岗/地点/薪资是否存在硬冲突。先改最可能影响当前进展的一处，用后续真实反馈检查，不因没回应机械改全部简历。

跟进间隔根据招聘时间、对方约定和消息上下文决定，不默认一天多次或无差别群发。给简短跟进稿与停止打扰的条件；没回复仍记未知，不替招聘者宣布拒绝。若用户沮丧，先回应感受，再把可控行动缩小到能执行的程度。

需要持续管理时用一张简单表记录公司/岗位、来源链接、申请日期、材料版本、实际状态和约定时间。没有承诺的下一次联系只是建议，不自动创建必须执行的催促。

平台来源与界面测算见[平台依据](platform-evidence.md)。
