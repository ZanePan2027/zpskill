# 网站视觉人格生成

## 1. 从人和任务取样

分别提取：目标岗位的信任来源、候选人的工作方式、证据形态、职业阶段、真实视觉资产、用户偏好与反偏好。参考网站只用于讨论关系和气质，不复制组件、代码、插图或动效。

## 2. 形成视觉指纹

输出：视觉性格词、反向禁区、阅读节奏、图文关系、字体角色、色彩角色、形状与边界语言、图片裁切原则、交互强度和动效上限。每项都要能追溯到输入事实。

## 3. 生成设计方向

高不确定性时内部比较两个黑白结构不同、视觉关系不同的方向。已有清楚约束则自主完成一个合适候选，仅用户要求选择时才停下。颜色变化不算新方向。每个方向都要回答：招聘者第一眼看什么；如何选择深读；证据怎样获得信任；为什么适合此人；何时会失败。

分别记录六项结构签名：入口形态、首个证据形态、主阅读轴、案例关系、数字角色、联系收束。候选方向至少三项不同，否则继续生成，不进入配色。

用户选择的是一组关系与气质，不是要求 Agent 永久照搬某张参考图。

## 4. 生成 token

结构通过后再生成背景、正文、弱文字、分隔、强调、状态、尺寸、间距、圆角和动效 token。token 的角色固定，具体值按方向生成；禁止在 Skill 中预设蓝色、橙色、深色页尾或等宽卡片。颜色按信息角色分配，一色一义：内容、可点击、当前位置或标记、状态，各用一种，不为装饰另加色（成品例：墨色是内容，蓝色只用于可点击，橙色标出你在哪）；具体色值和母题按人确定。

## 5. 反模板测试

使用最近邻反例，而非只换成完全不同职业：选择岗位层级或证据形态相近，但信任机制、职业阶段、渠道或资产不同的候选人。若结构高度相似，检查它是否遗漏当前候选人的关键差异。只有遗漏影响证据表达、扫读或渠道使用时，才回到结构修改；相似本身不要求重做。

“顶部导航 + 大字 hero + 横向指标带 + 1:2 分栏案例 + 联系终章”不是禁用结构，但它是高频默认骨架。按当前证据与阅读任务判断是否合适；出现阅读或证据表达问题时，再比较取消指标带、取消 hero 或改变主阅读轴的方案，不为追求新奇而改变有效结构。
