# 视觉与 PDF 验收

## 关系优先

- 大模块之间的间距大于模块内部间距；
- 标题与上一模块有分离，与下一内容有归属；
- 同类内容使用同一节奏；
- 页面不以挤满为目标，也不用大色块掩盖空白；
- 先调整全局变量，不给每段经历叠加不同补丁。

字号、行距、页边距和页数从字体实际字面、内容长度、渠道与打印场景推导，不预设固定数值。分页优先落在完整语义边界。

## 让“关系”能量出来

下面这些是检查线索，不是固定参数，用真实字体和内容渲染后再校准：

- 标题上方的距离约为下方的两倍以上，同一组内部的间距不超过组间的一半；同一条目内不要同时用缩进和段距两种分隔；
- 正文行高比标题宽松，中文正文通常比拉丁文再放宽一点，中文不使用负字距；
- 数字用等宽数字，让指标上下对齐；
- 字体角色最多两个家族：标题、正文各一，标签和数字沿用其一；
- 中英混排、多语言版本必须在真实内容和真实回退字体下重新排，不沿用原语言的参数；
- Word 版用命名样式，不用手动空行；标题设为与下段同页，开启孤行寡行控制；
- 页边距别窄到打印后贴边，四边最小文字边距用脚本看一眼。

## 招聘方的疑虑清单与首屏

动笔前先列招聘方看到这份简历可能的疑虑（年限不够、行业不对、空窗、频繁换工作、没有结果），每条对应简历里已有的证据或要怎么写。写完后只看最上面三分之一：是否同时看得到目标岗位、最强的匹配、一个结果和作品集入口（有的话）。缺哪项补哪项，不为凑项加内容；扫读层级已经满足时不重复做。

## 机器会读成什么样

PDF 版面好看不等于被系统读对。双栏或侧栏简历可能被按错误顺序读出，用空格拉开的标题可能被拆成单字，联系方式可能排到最后或丢失。脚本的 `--text-layer` 会提示这几项（读取顺序是否在栏间跳动、标准小标题是否存在、联系方式是否在最前几行、是否有大量单字拆分、最小字号、末页内容高度），它们只是线索：看到提示就回到渲染图确认，再决定改不改。国内平台的实际解析行为没有公开资料，这里按通用做法兜底，不对任何平台作保证。

## 组件验收

若使用标题栏、结果卡、时间线、侧栏或二维码，按实际字体和内容高度计算，不用固定基线猜测视觉居中。组件必须提供扫读或关系价值，不能只为填空。

## 连续页面验收

以足够识别字体与边缘的分辨率渲染全部页面，按内容边界切成连续阅读带，从第一页顶部看到最后一页底部。两页且结构适配时可以切成六帧；其他页数不得硬套。

每个阅读带同时检查：上方分离、下方归属、同类间距、视觉居中、断行、孤字、裁切、重叠、乱码、链接、页尾平衡和打印对比度。

任何视觉参数变化后重看全部阅读带。局部截图、文本抽取、页数正确和脚本无报错不能替代整份验收。

同时复核页数决策。除明确的封面页或作品跨页外，若最后一块有效内容停在页面上方约三分之二以内，下面空白不承担分组、批注、图像或行动任务，当前版本不得通过：至少生成一份更少页或重新分配跨页内容的实图作对照。若更少页导致字号过小、密度失衡、删除关键证据或破坏语义边界，合同需记录对照结果后才可保留原页数。反过来，某页因压缩出现过密、字号过小或语义跨页时，重新试排更多页。

## 机器初检

按项目真实要求运行：

```bash
python3 scripts/check_resume_pdf.py resume.pdf \
  --pages <项目页数> \
  --require '<必要文本>' \
  --forbid '<禁用文本>' \
  --require-link
```

机器检查页面尺寸、页数、必要文本、禁用词、空白页与链接注释；加 `--text-layer` 还会给出机器阅读的线索（见上）。无法判断阅读气势、疏密、视觉人格或 AI 味。

脚本优先使用 `pypdf`；缺少依赖时会尝试系统 `pdfinfo` 的降级检查。降级结果必须标记能力缺口，不得把未检查的项目写成通过。

## 发布边界

- 候选版：机器与内部视觉检查完成；
- 用户确认版：内容与视觉已确认；
- 正式投递版：文件名、链接、二维码、版本和跨载体数据已复验。

用户确认成品不自动授权部署网站或替换线上资产。
